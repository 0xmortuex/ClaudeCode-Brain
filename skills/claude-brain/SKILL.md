# Claude Brain — vault recall

A local-only archive of past Claude Code sessions lives at:

    C:\Users\USER\IdeaProjects\ClaudeCode-Brain\vault\

It indexes 13 projects, 73 sessions, 225 topic hubs, 62 tools, 46 entities.
This skill makes you recover that history *before* answering, so you respond
grounded in what actually happened — not from a guess.

## When to activate

Activate ONLY when the user's message contains a recall trigger. Match
case-insensitively, substring is enough:

- `let's work on` / `lets work on`
- `last time` / `last time on`
- `check my brain` / `check the brain` / `check my vault`
- `continue with` / `continue on` / `pick up where`
- `what did we do on` / `what did we do with`
- `remind me about` / `remind me what`

If none appear, DO NOT activate — work normally. The vault is for deliberate
recall, not a lookup on every message.

## Read protocol

Strictly read-only and budget-capped. Follow in order; stop once you have
enough context or hit the token budget.

1. **Resolve the project.** Read `vault\README.md`. It has a project table
   (name → `projects/<name>/_project.md`). Match the user's subject to a
   project name; a loose match is fine ("Vex" → `vex`). If nothing matches,
   tell the user the vault has no such project and proceed normally.

2. **Read the project rollup.** Read `vault\projects\<name>\_project.md`.
   It lists every session newest-first with dates and message counts.

3. **Skim recent sessions.** Read the **3 most recent** session files from
   the top of the rollup table (`projects/<name>/sessions/YYYY-MM-DD_*.md`).
   Read the start of each for recent state, decisions, and what shipped —
   you do NOT need the whole file.

4. **Topic hubs (only if the user named a topic).** If the user mentioned a
   specific topic/tool/entity, consult `vault\TOP-TOPICS.md` and read the
   matching `vault\topics\<slug>.md`, `vault\tools\<slug>.md`, or
   `vault\entities\<slug>.md` hub page. Skip this step otherwise.

5. **Respond, grounded.** Open with a one-line recap of where the project
   left off ("Last on Vex (2026-05-17): …"), then answer the actual request.

## Token budget

Cap total vault reading at ~10,000 tokens per session start. README +
_project.md + 3 session skims fit comfortably. If a session file is large,
read only its first ~150 lines. Never read more than 3 session files. Never
read every project rollup.

## Read-only — never write

This skill NEVER writes, edits, moves, or deletes anything under `vault\`.
Read only. The vault is regenerated by `sync-vault.py` in the brain repo. If
the user wants the vault refreshed, point them at that script — do not edit
vault files yourself.

## Fallback — fail silent

If the vault path does not exist, `README.md` is missing, or a file is
unreadable/corrupt: do NOT raise an error, do NOT mention it. Silently skip
vault recall and answer normally, as if this skill were not installed.
